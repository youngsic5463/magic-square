# Magic Square TDD Practice

## 목적

4×4 마방진 솔루션을 TDD(Test-Driven Development) 방식으로 구현하는 연습 프로젝트입니다.

이 저장소는 사람 개발자와 AI 코딩 에이전트가 함께 참고하는 **프로젝트 지도**입니다. 모든 테스트와 구현은 **계약 ID**(INV-*, E-*)를 기준으로 추적합니다. 계약 ID는 테스트와 구현을 잇는 “추적의 못”이며, 현재 단계는 **RED 준비 단계**입니다.

## 핵심 원칙

- **ID에 없는 동작은 만들지 않는다.** 계약 목록에 없는 기능·예외·UI는 구현하지 않습니다.
- **테스트가 먼저다.** 구현보다 실패하는 테스트가 항상 앞섭니다.
- **RED → GREEN → REFACTOR** 순서를 따릅니다.
- **과잉 구현을 금지한다.** 테스트를 통과시키는 최소 코드만 작성합니다.

## 계약 ID 목록

| ID | Contract | Evidence Level | Product Layer |
|---|---|---|---|
| INV-1 | 마방진의 크기는 4×4이다 | L0 — “4x4 마방진” 반복 언급 (#1, #9) | Core |
| INV-2 | 격자에는 사용되지 않은 숫자와 이미 배치된 숫자가 구분 가능해야 한다 | L0 — “사용되지 않은 숫자가 뭔지 몰라” (#2) | Core |
| INV-3 | 가로·세로·대각선 각각의 합을 산출·표시할 수 있어야 한다 | L1 — “직선, 대각선을 모두 … 계산” (#3) | Core |
| INV-4 | 각 숫자는 격자 전체에서 최대 1회만 배치된다 | L1 — 중복 입력 시 오답 (#2) | Core |
| INV-5 | 완성 상태에서 모든 직선·대각선의 합이 동일해야 한다 | L1 — 직선·대각선 합을 반복 검산 (#3) | Core |
| INV-6 | 마방진 조건 충족 여부를 검증할 수 있어야 한다 | L1 — 장시간 풀이 후 확인을 생략 (#7) | Trust |
| INV-7 | 사용 가능한 숫자는 1~16의 정수이며 각각 1회만 쓰인다 | L2 — 4×4 + 미사용/중복 맥락 → 표준 마방진 숫자 집합 추론 | Core |
| INV-8 | 모든 직선·대각선의 목표 합은 34이다 | L2 — 4×4 마방진 표준 magic constant; 인터뷰는 “합이 같아야 함”만 언급 (#3) | Core |
| E-1 | 같은 숫자는 중복 입력·배치할 수 없다 | L0 — “같은 숫자를 중복으로 채워넣어서 오답” (#2) | Trust |
| E-2 | 이미 배치된 숫자를 미사용 숫자 목록에 표시하지 않는다 | L1 — 미사용 숫자 혼동 (#2) | Trust |
| E-3 | 마방진 조건을 만족하지 않는 상태를 정답으로 표시하지 않는다 | L1 — 오답·검증 생략 (#2, #7) | Trust |
| E-4 | 숫자가 아닌 값은 칸에 입력할 수 없다 | L2 — 계산 실수·계산기 사용 맥락에서 숫자 입력 전제 추론 (#1, #6) | Safety |
| E-5 | 1~16 범위 밖의 숫자는 입력할 수 없다 | L2 — 중복·미사용 숫자 관리 전제 (#2) | Trust |
| E-6 | 빈 칸이 아닌 칸에 빈 값으로 덮어쓰기 할 수 없다 | L2 — “잊어버려서 처음부터” → 부분 상태 보존 필요 추론 (#1) | Safety |

## 계약 ID 설명

- **INV-1** — 격자는 항상 4행 4열(4×4)이어야 합니다.
- **INV-2** — 각 칸이 비어 있는지, 어떤 숫자가 들어 있는지, 아직 쓰이지 않은 숫자가 무엇인지 구분할 수 있어야 합니다.
- **INV-3** — 행·열·대각선별 합을 계산하고 그 결과를 확인할 수 있어야 합니다.
- **INV-4** — 1~16 각 숫자는 격자 전체에 최대 한 번만 놓일 수 있습니다.
- **INV-5** — 완성된 상태에서는 모든 직선(행·열)과 대각선의 합이 서로 같아야 합니다.
- **INV-6** — 현재 격자가 마방진 조건을 만족하는지 검증할 수 있어야 합니다.
- **INV-7** — 사용 가능한 숫자 집합은 1부터 16까지의 정수이며, 각 숫자는 정확히 한 번만 사용됩니다.
- **INV-8** — 4×4 마방진의 목표 합(magic constant)은 34입니다.
- **E-1** — 이미 배치된 숫자와 동일한 값을 다시 입력·배치할 수 없습니다.
- **E-2** — 격자에 이미 들어 있는 숫자는 미사용 숫자 목록에 나타나지 않아야 합니다.

## 계층 의미

- **Entity** (`src/square.py`) — 순수 도메인 계산 로직을 담당합니다. 불변식(INV-*)과 핵심 규칙을 구현하며, Flask 등 Boundary 계층을 import하지 않습니다.
- **Boundary** (E-*) — 입력 검증·표시 규칙 등 사용자 경계에 가까운 계약입니다. 본 실습에서는 별도 UI 없이 **도메인 함수 진입점에서 검증**합니다.

```text

│   └── square.py
└── tests/
    └── test_square.py
```

## TDD 진행 순서

1. **RED** — 계약 ID별로 실패하는 테스트를 먼저 작성합니다. 이 단계에서는 `tests/`만 수정하고 `src/`는 건드리지 않습니다.
2. **GREEN** — 해당 계약 ID를 만족하는 **최소 구현**만 추가합니다. 구현 줄에는 충족한 계약 ID를 주석으로 표기합니다.
3. **REFACTOR** — 모든 테스트가 통과한 뒤에만 구조를 개선합니다. 리팩터 전후로 `pytest -q`로 동작 불변을 확인합니다.

## 테스트 실행

```bash
pytest -q
```

`-q`는 quiet mode로, 테스트 결과를 간략하게 출력합니다.

## 구현 금지 사항

- 계약 ID에 없는 **예외 처리**를 임의로 추가하지 않습니다.
- **UI, CLI, DB, API** 코드를 추가하지 않습니다.
- 계약 목록에 없는 기능을 미리 구현하지 않습니다(과잉 구현 금지).
