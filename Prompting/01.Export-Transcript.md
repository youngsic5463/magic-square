# MagicSquare — MomTest 인터뷰 기반 제품 계약 도출

_Exported on 2026-06-25 from Cursor_

**관련 보고서:** [Report/01.REPORT.md](../Report/01.REPORT.md)

---

## User

다음은 "4x4 마방진 솔루션" 서비스 기획을 위한 맘 테스트 고객 인터뷰 응답이다.

1. 4x4 마방진을 완성하려는데, 숫자 계산을 계속 실수해. 자꾸 잊어버려서 처음부터 다시 시작하느라 1시간 이상 썼어
2. 사용되지 않은 숫자가 뭔지 몰라서 같은 숫자를 중복으로 채워넣어서 오답이 발생해
3. 직선, 대각선을 모두 10번 반복해서 계산하다보니 헷갈리고 피곤해
4. 해결하려고 사용한 숫자는 다른 곳에 기입하고, 완성된 라인은 색칠이나 선을 그었어
5. 하다가 막혀서 도저히 답이 안나오면 그냥 포기하고 다른 문제를 시도했어
6. 해결을 위해 친구에게 물어보거나 계산기나 엑셀을 이용하기도 했어
7. 문제 해결에 시간이 오래 걸린 경우 맞았는 지 확인하는 것도 피곤해서 확인 안하고 넘어간 적도 많아
8. 만약 이런 일을 또 하게 된다면 보수가 없을 경우 그냥 포기할 것 같아. 누가 대신 해줬으면 좋겠어
9. 취미 활동 및 정신 건강을 위해 하루에 4x4 마방진을 10번씩 풀어보는데 오히려 스트레스가 쌓여

이 응답을 바탕으로 제품 기획용 계약(Contract)을 도출하라.

출력 형식:

1. 고객의 반복 문제
   - 매일 반복되는 마방진 해결 과정에서 불편을 구체적 빈도/시간과 함께 정리

2. 실제 행동 증거
   - "~하면 좋겠다"가 아닌, 인터뷰에서 드러난 과거 실제 행동만 추출

3. 현재 대안
   - 고객이 이미 사용 중인 해결책 (계산기나 엑세 사용 등)과 각 대안의 한계

4. 비용 또는 시간 손실
   - 시간 손실을 서비스 이용으로 전환할 수 있는지 수치로 산출

5. 제품이 반드시 만족해야 할 불변식 (INV)
6. 제품이 반드시 막아야 할 에러 조건 (E)
7. MVP 기능 후보
8. 아직 만들면 안 되는 기능

---

불변식은 다음 형식으로 작성하라.

ID | Contract | Evidence Level | Product Layer

Evidence Level 기준:
- L0: 인터뷰에서 직접 언급된 과거 행동 + 금액/시간 수치 동반
- L1: 인터뷰에서 직접 언급된 과거 행동 (수치 불명확)
- L2: 행동에서 합리적으로 추론 가능하나 직접 언급은 없음

Product Layer 기준:
- Core: 제품의 핵심 가치를 구성하는 계층
- Trust: 사용자 신뢰 확보에 필요한 계층
- Safety: 위반 시 사용자에게 직접 손해가 가는 계층
- Convenience: 편의성 계층 (MVP 이후 고려)

---

예시:

INV-1 | 마방진의 크기는 4x4 이다  | L0 | Core
INV-2 | 채워야할 빈칸은 2개이다  | L0 | Core
INV-3 | 가로, 세로, 대각선의 합은 34 이다 | L0 | Core
E-1 | 빈칸에 숫자가 아닌 값은 입력할 수 없다 | L0 | Safety
E-2 | 같은 숫자는 중복될 수 없다 | L0 | Trust
E-3 | 1에서 16 사이의 값이 아닌 숫자는 입력할 수 없다  | L0 | Trust

---

작성 규칙:
- 모든 INV와 E는 반드시 인터뷰 응답의 구체적 발언이나 행동을 근거로 할 것
- Evidence Level이 L2인 항목은 근거가 된 추론 경로를 한 줄로 병기할 것
- MVP 기능 후보는 INV 중 L0~L1 항목을 직접 충족하는 기능만 포함할 것
- "아직 만들면 안 되는 기능"은 Evidence Level이 L2이거나 인터뷰에서 행동 증거가 없는 니즈 기반 기능을 포함할 것

## Cursor

인터뷰 응답만을 근거로 MomTest 계약을 도출했다. 수학적 사실(합=34, 1~16)은 발언에 없으므로 **L2 추론**으로 표기했고, MVP는 **L0~L1 INV만** 직접 충족하는 기능으로 한정했다.

---

### 1. 고객의 반복 문제

| 문제 | 빈도/시간 | 근거 발언 |
|------|-----------|-----------|
| 숫자 계산 실수 → 잊어버림 → 처음부터 재시작 | **1회 60분 이상** 소요 | #1 |
| 미사용 숫자를 모름 → 같은 숫자 중복 입력 → 오답 | 빈도 미기재, **반복 발생** | #2 |
| 가로·세로·대각선 합을 **각각 약 10번** 반복 계산 | 문제 1회당 **~100회** 합산(10선 × 10회) | #3 |
| 수동 보조 기록(사용 숫자 메모, 완성 라인 표시)에도 혼란 지속 | 매 시도마다 | #4 |
| 막히면 **포기 후 다른 문제**로 전환 | 빈도 미기재 | #5 |
| 장시간 풀이 후 **정답 확인 생략** | “많은” 경우 | #7 |
| 취미 목적 **하루 10문제** 시도 → 스트레스 누적 | **매일 10회** | #9 |

**일일 반복 패턴:** 하루 10문제 × (합산 반복 + 수동 기록 + 검증 생략/포기). 최악 세션은 **문제 1개만 60분+**.

---

### 2. 실제 행동 증거

(과거 실제 행동만. #8의 “보수 없으면 포기”, “대신 해줬으면”은 **미래 가설**이므로 제외.)

| 행동 | 근거 |
|------|------|
| 계산 실수 후 처음부터 다시 풀었다 | #1 |
| 같은 숫자를 중복으로 넣어 오답을 냈다 | #2 |
| 직선·대각선 합을 각각 약 10번 반복 계산했다 | #3 |
| 사용한 숫자를 **별도 장소에 기입**했다 | #4 |
| 완성된 라인에 **색칠·선**을 그었다 | #4 |
| 막히면 **포기하고 다른 문제**를 시도했다 | #5 |
| **친구에게 물어봤다** | #6 |
| **계산기**를 사용했다 | #6 |
| **엑셀**을 사용했다 | #6 |
| 오래 걸린 경우 **맞는지 확인하지 않고 넘겼다** | #7 |
| 정신 건강·취미 목적으로 **하루 10번** 4×4 마방진을 풀었다 | #9 |

---

### 3. 현재 대안과 한계

| 대안 | 실제 사용 근거 | 한계 |
|------|----------------|------|
| 수동 메모(사용 숫자 기록) | #4 | 미사용 숫자 혼동·중복 오답 지속 (#2) |
| 라인 색칠·선 표시 | #4 | 합 계산 반복·피로는 해소 못 함 (#3) |
| 계산기 | #6 | 합을 **10번 반복** 검산하는 부담은 그대로 (#3) |
| 엑셀 | #6 | 중복 방지·미사용 숫자 추적이 자동이 아님 (#2) |
| 친구에게 질문 | #6 | 가용성·즉시성 한계, 반복 10문제/일에 비현실적 (#9) |
| 포기 후 다른 문제 | #5 | 미완료, 시간은 이미 소모 |
| 정답 확인 생략 | #7 | 정답 여부 불명, 학습·취미 목적 훼손 (#9) |

---

### 4. 비용 또는 시간 손실

#### L0로 확인된 수치

| 항목 | 수치 | 산출 |
|------|------|------|
| 최악 1문제 소요 | **≥ 60분** | #1 |
| 일일 시도량 | **10문제/일** | #9 |
| 합산 반복 강도 | **선마다 ~10회** × 10선(가로4+세로4+대각2) ≈ **100회 합산/문제** | #3 |

#### 서비스로 전환 가능한 시간(추정)

| 절감 항목 | 가정 | 절감 추정 | 근거 수준 |
|-----------|------|-----------|-----------|
| 중복·실수로 인한 **재시작** | 최악 세션 60분 중 상당 부분이 재작업 | **최대 ~60분/문제**(해당 세션 한정) | L0 |
| **합산 10회 반복** 제거 | 1회 합산 30초 가정 → 90회 절감 | **~45분/문제** | L2 — “10번 반복”에서 1회 자동 검산으로 대체 가정 |
| **정답 확인 생략** 방지 | 확인 1회 2~3분 × 생략 다수 | **수분~수십 분/일** | L1 — 빈도는 “많음”만 확인 |

**일일 잠재 손실(보수적):**

- L0만: 10문제/일 × (문제당 수 분~60분+) → **최소 수십 분, 최악 수 시간/일**
- L2 포함(자동 합산): 문제당 **~45분** 절감 가능 시 → 10문제 기준 **최대 ~7.5시간/일** 절감 상한(모든 문제가 수동 10회 검산을 하는 경우)

**전환 가치:** 중복 방지·미사용 숫자 표시·자동 합산·원클릭 검증이 #1·#2·#3·#7의 **실제 행동**에 직접 대응한다.

### 5. 제품이 반드시 만족해야 할 불변식 (INV)

| ID | Contract | Evidence Level | Product Layer |
|----|----------|----------------|---------------|
| INV-1 | 마방진의 크기는 **4×4**이다 | L0 — “4x4 마방진” 반복 언급 (#1, #9) | Core |
| INV-2 | 격자에는 **사용되지 않은 숫자**와 **이미 배치된 숫자**가 구분 가능해야 한다 | L0 — “사용되지 않은 숫자가 뭔지 몰라” (#2) | Core |
| INV-3 | **가로·세로·대각선** 각각의 합을 산출·표시할 수 있어야 한다 | L1 — “직선, 대각선을 모두 … 계산” (#3) | Core |
| INV-4 | 각 숫자는 격자 전체에서 **최대 1회**만 배치된다 | L1 — 중복 입력 시 오답 (#2) | Core |
| INV-5 | 완성 상태에서 **모든 직선·대각선의 합이 동일**해야 한다 | L1 — 직선·대각선 합을 반복 검산 (#3) | Core |
| INV-6 | 마방진 조건 충족 여부를 **검증**할 수 있어야 한다 | L1 — 장시간 풀이 후 확인을 생략 (#7) | Trust |
| INV-7 | 사용 가능한 숫자는 **1~16의 정수**이며 각각 1회만 쓰인다 | L2 — 4×4 + 미사용/중복 맥락 → 표준 마방진 숫자 집합 추론 | Core |
| INV-8 | 모든 직선·대각선의 목표 합은 **34**이다 | L2 — 4×4 마방진 표준 magic constant; 인터뷰는 “합이 같아야 함”만 언급 (#3) | Core |

### 6. 제품이 반드시 막아야 할 에러 조건 (E)

| ID | Contract | Evidence Level | Product Layer |
|----|----------|----------------|---------------|
| E-1 | **같은 숫자는 중복** 입력·배치할 수 없다 | L0 — “같은 숫자를 중복으로 채워넣어서 오답” (#2) | Trust |
| E-2 | 이미 배치된 숫자를 **미사용 숫자 목록**에 표시하지 않는다 | L1 — 미사용 숫자 혼동 (#2) | Trust |
| E-3 | 마방진 조건을 만족하지 않는 상태를 **정답**으로 표시하지 않는다 | L1 — 오답·검증 생략 (#2, #7) | Trust |
| E-4 | **숫자가 아닌 값**은 칸에 입력할 수 없다 | L2 — 계산 실수·계산기 사용 맥락에서 숫자 입력 전제 추론 (#1, #6) | Safety |
| E-5 | **1~16 범위 밖**의 숫자는 입력할 수 없다 | L2 — 중복·미사용 숫자 관리 전제 (#2) | Trust |
| E-6 | 빈 칸이 아닌 칸에 **빈 값**으로 덮어쓰기 할 수 없다 | L2 — “잊어버려서 처음부터” → 부분 상태 보존 필요 추론 (#1) | Safety |

### 8. 아직 만들면 안 되는 기능

| 기능 | 보류 사유 |
|------|-----------|
| **완전 자동 풀이 / 대리 해결** | #8은 미래 가설(“해줬으면”), 과거 행동 아님 |
| **보수·결제·인센티브** | #8 가설 기반, 행동 증거 없음 |
| **스트레스·정신건강 트래킹** | #9는 결과 서술, 완화 수단에 대한 행동 없음 |
| **일일 10문제 챌린지·게이미피케이션** | #9는 현재 습관이지 “챌린지 원함” 증거 아님 |
| **친구 초대·소셜 풀이** | 친구에게 물어본 적은 있으나(#6), 제품 내 소셜 요구 미언급 |
| **엑셀 가져오기/보내기** | 엑셀 사용(#6)은 있으나 연동 니즈 미확인 |
| **내장 계산기 모드** | 계산기 사용(#6)은 있으나, 자동 합산(INV-3)으로 대체 가능 — 별도 니즈 L2 |
| **힌트·단계별 가이드** | 막히면 포기(#5)는 있으나 힌트 요청 없음 |
| **5×5 이상·다른 크기** | 인터뷰 전부 4×4 한정 |
| **풀이 이력·세션 복원** | “잊어버림”(#1)에서 추론 가능하나 직접 언급 없음 → L2 |
| **목표 합 34 고정 표시** | INV-8이 L2 — 사용자가 “34”를 말하지 않음, MVP 이후 검증 권장 |

---

#### L2 항목 추론 경로 요약

- **INV-7:** 4×4 + 미사용/중복 → 표준 1~16 일회 사용 집합
- **INV-8:** 4×4 마방진 도메인 + “직선·대각선 합 동일” 검산 행동
- **E-4:** 계산기·숫자 계산 맥락 → 칸 입력은 숫자만
- **E-5:** 미사용 숫자 집합 관리 → 유효 범위 밖 차단
- **E-6:** 잊어버림·재시작 → 부분 진행 상태 보호

다음 단계로 이 계약을 `tests/entity`(INV) · `tests/boundary`(E) 테스트 ID에 매핑할 수 있다. 원하면 RED 테스트 스켈레톤부터 작성하겠다.
